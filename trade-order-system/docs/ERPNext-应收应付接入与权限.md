# Tradept 原生应收、应付账款管理

Tradept 的财务工作台使用同一 ERPNext 站点内的销售发票、采购发票、收付款单、付款核销、银行流水和账簿。账单金额、未结余额、汇兑差额、过账和账龄均由 ERPNext 原生控制器计算；工作台不维护第二套应收应付余额。Grandware 与其他租户使用不同站点数据库，同租户多个法人主体按原生公司授权隔离。

## 使用流程

1. 企业管理员在「管理中心 → 角色与权限」明确应用标准财务模板，或逐项设置自定义角色。既有工作区不会因升级自动获得新增权限。
2. 在「应收与应付」选择公司，从已提交的销售订单、送货单、采购订单或采购收货单创建账单；也可用真实 ERP Item 创建独立账单草稿。
3. 检查商品、数量、税费、付款条款、到期日和记账汇率，保存并提交。草稿保存不产生正式账簿；提交后余额以原生账单为准。
4. 录入客户收款或供应商付款，可部分支付、分配至多张账单，或保留未分配余额为预收／预付。使用按付款条款分配的分期账单时，每行同时选择原生付款期；金额按往来账户币种填写。付款和到账账户可使用不同币种，双端金额与记账汇率分别填写。
5. 通过预付款核销将已过账但未分配的款项或贷项／借项匹配账单；通过银行对账将银行实际流水匹配收付款凭证。读取原生应收／应付账龄和总账，打印或导出需单独授权。错配付款时，在已提交收付款单详情解除所选发票核销，付款凭证保留已提交状态；原生解除核销按整张发票处理，分期关联一并解除。
6. 已提交单据不能直接改写。使用原生取消、修订和销售贷项／采购退货调整，原生控制器验证关联单据、已收款、已核销和会计期间限制。

## 金额口径

| 信息 | 原生来源与含义 |
| --- | --- |
| 订单金额 | Sales Order 的合同金额；尚未开票部分不是发票应收 |
| 账单金额 | Sales／Purchase Invoice 的总额及账单币种 |
| 未结应收／应付 | 原生 outstanding_amount，按往来会计账户币种展示，可能与账单币种不同 |
| 客户核销金额 | Payment Entry 的总分配金额，按往来账户币种展示 |
| 银行收付金额 | Payment Entry 双端账户金额及各自币种 |
| 银行实际净到账 | Bank Transaction 的存入／支出金额和匹配结果；费用在原生收付款科目中记录 |
| 本位币金额 | 原生 base 金额及公司本位币，禁止跨币种直接相加 |

例如同币种客户结清 100、银行净收 97、手续费 3：原生收付款单双端金额为 97，账单分配金额为 100，费用为 3；ERPNext 记录银行 97、费用 3、应收结清 100。同币种双端不能填写不等金额。外币发票的余额可能使用不同的往来账户币种，工作台分别标识。

Grandware 历史 Excel 中的金额、字符串和参考收款记录继续保留；这些历史参考不会自动重放为新发票或银行凭证。物流 CI／PL 单证也不会被当作会计发票。原有订单利润分析与正式账簿口径应分别使用。

正式订单还回显原生订单预收／预付、来源发票的已核销和未结清金额。共用发票按原生商品来源分摊到各订单，避免每个订单重复取整张发票金额。兼容字段 `paidAmountUSD`／`factoryPaidRMB` 在 `nativeSettlementProjection=true` 时表示订单预收／预付加发票已核销金额，包含非现金贷项抵账；界面使用结算标签，不能把它当银行现金。`nativeReceiptSummary` 的银行凭证整额仅供核对，带 `additiveByOrder=false`，禁止按订单重复加总。解除发票核销恢复应收，但已到账的付款凭证仍保留为未分配款。

已存在提交发票的订单从账单登记收付款，旧“登记订单预收款”入口拒绝继续为该订单新增预收，防止按旧订单余额重复收款。只读结算字段和银行摘要不能由 Excel 或页面保存回写。

## 权限配置

权限先检查当前租户、配置角色和原生 Company User Permission 的交集，再检查个人／团队／企业数据范围。来源订单、商品明细、客户／供应商、科目、银行账户、退货来源、核销引用等均再次验证。仅有原有 finance.write 不等于获得所有新财务能力。

| 资源 | 可分别授权的操作 |
| --- | --- |
| 销售账单／采购账单 | 查看、创建、修改、提交、取消、修订、退货调整、打印、导出 |
| 收付款单 | 查看、创建、修改、提交、取消、修订、费用与核销差额、打印、导出 |
| 银行流水 | 查看、创建、修改、提交、取消、打印、导出 |
| 预付款核销 | 查看、执行匹配、单独授权的解除发票核销、打印、导出 |
| 银行对账 | 查看、执行匹配／解除银行匹配、打印、导出 |
| 应收账龄／应付账龄／总账 | 查看、打印、导出 |
| 银行资料 | 独立查看权限；未授权时隐藏银行标识与相关银行科目名称 |

角色还可限制财务数据范围、允许使用的银行账户，以及按明确原生币种配置单笔付款限额。限额不采用浏览器传入的汇率换算来绕过币种限制。公司全账报表、核销、银行流水和银行对账要求企业财务范围；个人和团队财务角色只访问其获授权业务单据。能提交发票不要求同时能修改来源销售订单。

解除发票核销使用 `finance.reconciliation.unreconcile`，不随 `finance.reconciliation.write` 自动授权。解除银行流水匹配和取消付款凭证是另外的操作，不能互相替代。

授权每次请求重新读取，撤回后已有会话同样失效。配置账号不能通过原生 REST、Desk 或任意 RPC 绕过工作台授权。原生管理和修复账号的用途独立于工作台账号。

仅保留 Tradept 原生角色但缺少成员资料的账号同样受入口限制，不能被当作原生运维操作员。停用成员的历史归属仍按原部门和公司范围判断；该成员不能登录，也不能被重新分配新业务。

## 并发、审计与恢复

所有财务写操作在原生数据库同一事务内进行，同时检查工作区版本和已有单据 modified 时间，并使用稳定请求标识记录原生审计回执。超时后复用原请求，避免重复记账；不同意图使用同一标识会被拒绝。

发生冲突后保留原草稿并展示服务器最新单据。旧草稿不会仅换一个版本号后直接重放；重新编辑以服务器最新字段为起点，避免把其他人的价格修改覆盖掉。

原生父单据、明细和账簿记录保留真实发起账号。授权委托不改变浏览器 SID／CSRF，也不把历史记录创建人改成系统管理员。工作区快照和审计用于查看变更，已过账财务数据的纠正走原生取消、退货和修订流程，不能用旧页面快照覆盖账簿。

## 验收边界

验收包括前端和权限回归、同源 HTTP 网关边界，以及独立原生镜像中的真实发票过账、收付款、核销、报表和银行对账。原生业务测试结束后回滚并核对数据库表指纹，另核对 Grandware 站点没有变更。浏览器预览使用独立测试站点。

具体执行结果、源代码摘要和版本发布状态以本轮验收记录为准；本文件不把代码实现、单元测试、原生执行和云端发布混为同一种完成状态。

本轮接入账单、收付款、预付款／贷项核销、解除付款核销、应收应付账龄、总账和银行对账的业务流程。原生打印格式设计器、自动邮件催收、在线支付服务商和银行接口的采购／配置不在此次界面接入范围；当前打印入口提供获授权的财务明细与报表打印。
