# Tradept 0.1.0 阶段交付与验收

日期：2026-10-12（开发始于 2026-10-11）。本地应用与真实隔离 ERPNext 已完成分项验收；Git 发布以远端标签、Release 和 CI 核验为准。本文记录首个通用产品开发版本的交付范围，不代表完整 PRD 已完成。

当前没有生产环境。本地 Tradept `127.0.0.1:3087`、隔离 ERPNext `127.0.0.1:3088` 和旧 CloudBase 在线系统均为测试环境。本文保留 0.1.0 已执行验收的范围与结果；后续测试环境更新以新的部署回读记录为准。

Tradept 是产品，Grandware 是优先服务的演示客户。版本使用 `大.中.小` 三个整数，拟发布源码标签为 `v0.1.0`，规则见 [VERSIONING](VERSIONING.md)。本地预览、自动测试、真实隔离 ERPNext 和 Git 发布分别记录，不能互相替代。

## 已测试与隔离验收

最终前端 14 套 636 项、后端 117 项全部通过，代码检查和版本一致性检查通过。本机使用 Node.js 24.19.0、Python 3.12.14；后端最终运行 24.482 秒，无失败、错误或跳过。自动验证记录分别在 [业务验收](BUSINESS-RELEASE-ACCEPTANCE.md) 和 [独立审查](RELEASE-REVIEW.md)。测试使用虚构数据、临时 SQLite、真实本机 HTTP 及明确标注的 FakeFrappe。它们证明覆盖场景的行为，不能替代特定测试环境的部署回读或完整 PRD 验收。

本地预览使用新 API。前期真实浏览器已完成桌面品牌、业务员生产编辑、订单出运创建与实际日期、双页面冲突及草稿保全。2026-10-12 使用保留的实际数据库再次完成销售/单证访问父订单与出运、备注保存、财务保全、409/403 拒绝。Grandware 的 payload、汇率和 revision 保持不变；与原始归档逐条比较，仅新增 `tenantId=grandware` 导入归属，原业务字段、顺序及汇率相等，见 [真实本地 API 记录](live-api-acceptance-20261012.json)。登录页完成桌面浅/深色与 390px 移动端真实浏览器捕获，见 [视觉记录](visual-acceptance-20261012.json)。完整移动端业务流程和规模化并发仍未验证。

真实 ERPNext 16.32.3 / Frappe 16.31.0 已在独立 Ubuntu ARM64 VM 部署，只通过本机 `127.0.0.1:3088` 访问，未挂载客户数据。虚构租户以 revision 9 显式排队，真实 API 创建 USD 1000 Sales Order 和两张 USD 420/280 Purchase Order 草稿。隔离验收脚本随后显式提交三张单据，创建数量 100 的 Delivery Note，回读交付 100%；Payment Entry 收 USD 1000，总账借银行 1000、贷应收 1000，SO `advance_paid=1000`。客户公司名及客户 PO 回读一致，见 [实际单据 JSON](erpnext-real-acceptance.json) 和 [ERPNext 验收记录](ERPNEXT-ACCEPTANCE.md)。

产品常规同步默认创建草稿，由本机管理员运行有限批次 worker；本轮未交付常驻调度。验收脚本中的提交仅针对虚构隔离站点。ERP 提交期间 Tradept 的业务 payload 和 revision 未变，收款聚合仍为 0；关联元数据可以刷新，但不代表业务双向回写或外部状态实时同步。Grandware 未配置 ERP，不发送其真实数据。

`package.json`、锁文件及入口资源版本为 `0.1.0`；[CHANGELOG](../CHANGELOG.md) 已列本阶段变更。正式版本对应 `wuyinhust/tradept` 的 `v0.1.0` 标签，远端发布与 CI 结果在主任务冻结源码后单独核验；本地工作区保留 Git 发布回执。
