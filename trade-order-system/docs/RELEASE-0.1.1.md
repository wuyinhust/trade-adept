# Tradept 0.1.1 测试环境更新

日期：2026-10-12。用户确认当前没有生产环境，所有现有部署均用于测试；云端更新目标为当前腾讯云账号中的独立 Tradept 测试环境。

## 本次改动

- 工作区状态改为“数据库工作区 · 测试环境”；本地服务启动提示与环境文档同步更正。
- 版本从 `0.1.0` 递增为 `0.1.1`，入口资源缓存参数同步更新。业务功能和两套需求的阶段验收继续参考 [0.1.0 验收矩阵](RELEASE-0.1.0.md)。
- 明确 `3086` 为早期浏览器快照测试，`3087` 为当前数据库 API 测试，`3088` 为隔离 ERPNext；示例快照预览使用其他端口，避免冲突。
- 新增云测试反向代理适配：固定 HTTPS Origin、严格 Host、Secure 会话 Cookie；Python 始终只监听本机回环地址。提供独立目录、可靠块盘与受限 systemd / Nginx 模板，见 [云测试部署说明](../integrations/cloud-test/README.md)。

## 已完成的本地更新与回读

本地 `http://127.0.0.1:3087/` 已重启，实际返回的入口 CSS、JS 缓存版本均为 `0.1.1`，数据库工作区标签符合测试环境说明。真实浏览器已刷新并显示登录页和 Tradept 标识。

配置账号登录、持久工作区读取与退出成功；未登录请求返回 401，跨 Origin 返回 403，私有配置静态路径返回 404。更新前后逐租户比较业务 payload、汇率、汇率说明与 revision 的摘要相同：Grandware revision 为 1，虚构 Example 租户为 9；SQLite `quick_check` 为 `ok`。登录回读没有修改业务数据。

隔离 ERPNext `http://127.0.0.1:3088/login` 返回 200；本补丁没有升级 ERP 软件或重新执行单据。原来的实际业务单据验收见 [ERPNext 记录](ERPNEXT-ACCEPTANCE.md)。

前端 14 套、636 项通过（89.692 秒），包含云测试适配的完整后端 130 项通过（32.180 秒），ESLint 与版本一致性检查通过。新增 13 项实际验证覆盖 Host / Origin、Secure cookie、默认本地兼容以及虚构 seed 首次导入后的重启持久化和租户隔离。

## 已完成的加密云测试更新

历史 Grandware CloudBase 在线系统也是测试环境。它的账号与当前腾讯云登录账号不匹配，实际资源查询确认无法用当前账号管理旧环境；原站点仍返回历史 v40 资源。本次按用户选择新建独立 Tradept 云测试环境。

当前腾讯云账号中已有的 Lighthouse 主机承载独立 `tradept-test` 服务、用户、代码目录和私有 SQLite。运行包的 41 个文件逐一核对 SHA-256；API 仅监听云主机 `127.0.0.1:3089`。测试服务限定 CPU 25%、内存 256 MiB、任务数 64；原主机应用的进程及配置校验值保持一致，没有新增付费主机。

用户选择通过 SSH 加密云预览验收。当前入口为 `http://localhost:3089/#/dashboard`，需要本机加密隧道运行。浏览器访问的是本机转发端口，数据库和 API 实际运行在云主机；端口不对公网开放。使用 `localhost` 区别于本地 `127.0.0.1:3087`，避免两个环境的会话 Cookie 相互覆盖。

新云环境使用公开源码内的虚构 Grandware Demo seed，包含四法人、4 客户、4 工厂、4 订单和4出运，以及独立的空 Example 租户。14 个配置账号的随机密码在云端重新生成；没有复制本机密码、真实 Grandware 导出或 ERP token。新云环境不启用 ERPNext；原隔离 ERPNext 继续在本地 `3088` 验收。

主任务通过加密入口实际验证版本资源、登录、401 / 403 / 404、公司及租户隔离、销售角色财务保密和写入拒绝。虚构订单备注保存使 revision 从 1 到 2，基于旧版本再次保存返回 409，金额、其他记录和汇率相同。单独重启 Tradept 服务后，新登录回读 revision 2 及完整业务摘要保持一致。实际检查元数据见 [测试更新记录](test-environment-update-20261012.json)，不含密码或业务 payload。

公网 HTTPS 未完成：临时测试域名的证书验证被云侧访问拦截，现有域名 DNS 的阿里云登录不可用。按用户选择保留加密私有预览；没有绕过 TLS 验证或以公开 HTTP 传输登录信息。将来启用公网入口需要可管理的域名与新的实际 HTTPS 验收。Git 源码发布与环境部署分别核验。
