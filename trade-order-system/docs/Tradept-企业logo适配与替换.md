# 企业 logo 适配与替换（可选，供 AI 执行）

返回 [guide](guide.md)。这一步只针对本企业私有部署。主人选择保留 Tradept logo 时，记录“保留原 logo”并继续安装。

## 1. 问主人并取得素材

用直白的话问：

> 要把页面上的 Tradept logo 换成企业自己的 logo 吗？想换的话，请提供原图，最好是 SVG 或透明背景的高清 PNG；有深色背景专用版、横版或小图标也可以一起提供。我会处理网页和深色模式的适配。不换也可以。

没有专用暗色版或图标时，你先根据已有素材处理，不要求主人准备所有规格。保留原始文件，先查看实际图像、尺寸、比例、透明通道、文字与品牌颜色；SVG 还需检查字体、嵌入图片及外部依赖。

只有低清截图时先处理可用版本；如果文字或图形已无法辨认，说明具体问题再请主人提供更清晰的原图。不要用生成的新图替代企业原有标识，也不要编造缺失的文字。

## 2. 制作网页用版本

你用可用的图像／矢量处理工具完成，不把裁图、调尺寸和导出工作交给主人。

- 保留品牌图形、文字、比例和标准颜色；去掉无关截图边框和多余留白。背景本来是标识的一部分时保留，不盲目抠白。
- 默认使用透明背景，给图形留适当边距，避免贴边、切字或切断图形。检查透明边缘在浅色、深色背景上没有白边或黑边。
- SVG 适合清晰缩放；去除脚本和外部资源依赖，必要时按实际显示效果处理字体。需要 PNG 时导出透明版本，分辨率至少覆盖实际显示尺寸的 2 倍，避免用 CSS 放大小图。
- 根据素材提供横向页面 logo 和方形 favicon／触屏图标；方形标识可以直接等比显示，不强行拉成横版。有独立图形时用于小图标，避免把长企业名称挤到 16 像素内。
- 采用 `object-fit: contain` 或等比尺寸，按登录页、侧栏和原生后台的实际容器调整。检查窄屏布局，不遮挡按钮、不导致侧栏或页面横向溢出。

建议在企业品牌资源目录保存 `enterprise-logo-light`、`enterprise-logo-dark` 和 `enterprise-icon`，格式按实际用途选择。保存原图、导出参数和文件校验信息，便于恢复与升级。

## 3. 适配 dark mode

先分别放到页面真实浅色和深色背景中预览。单一素材在两种背景都清晰时可以共用；不清晰时制作对应版本。

- 有官方暗色版时优先使用。
- 只有深色文字时，保持彩色图形不变，按企业品牌允许的方式处理文字；必要时用有边距的中性底板承载原标识。
- 不默认整图反色，不把品牌彩色图形一并变白。原标识不可改色时优先使用底板；效果仍不清楚时给主人看预览，再确定处理方式。
- 沿用页面实际主题状态，兼容手动选择 light／dark 和首次跟随系统 `prefers-color-scheme`。主题切换后 logo 应立即对应变化，不出现两张图叠印、闪白或文字消失。
- 原生 ERPNext Desk 的主题机制须在目标版本中另外检查，不能直接假定与 Tradept 的 `data-theme` 完全相同。

## 4. 找到并替换界面引用

在从 `wuyinhust/trade-adept` 取得的冻结源码中先查询引用，修改本企业部署副本，不直接覆盖上游仓库：

```sh
cd <源码仓库>/trade-order-system
rg -n 'tradept-(logo|icon)|brand-logo|app_logo|banner_image|footer_logo|favicon|apple-touch-icon' \
  index.html css integrations/frappe_app/tradept_core
```

本地源码中已发现下列入口；所选正式版本可能不同，你须实际核对：

| 位置 | 要处理的内容 |
|---|---|
| `index.html`、`assets/brand/` | 登录页、侧栏 logo，favicon 和 apple-touch-icon；图片 alt／相关可访问名称与企业标识一致 |
| `css/design-v1.css` | logo 容器、比例、定位、裁切和主题适配 |
| `tradept_core/public/images/` | 原生后台与站点使用的 logo／图标；目录位于 `integrations/frappe_app/` 内 |
| `tradept_core/branding.py` | Website Settings、Navbar Settings、boot 中的 logo、banner、footer 与图标路径 |
| `tradept_core/public/js/desk-brand.js` | 运行时写入的 logo 路径；只改设置可能被这个脚本重新覆盖 |
| `tradept_core/public/css/desk-brand.css` | 原生导航 logo 显示尺寸及主题样式 |

**现有 Tradept logo 有专用裁切和深色叠图，不能仅换同名 PNG。** 本地 `design-v1.css` 使用固定比例、负偏移、`clip-path` 和白色文字叠层；这些参数依赖原图中图形与文字的位置。换企业素材后，调整或移除旧裁切、偏移和叠层，按新素材完整等比显示，并接入对应主题资源。

优先用独立企业资源文件和明确路径，方便保留原 logo 及回退。若同名替换，要更新缓存标识并确保浅／深色处理仍正确。替换登录、侧栏、原生后台及浏览器图标的所有实际可见入口，不能只改其中一处。不要做全仓库字符串替换，产品接口、应用 ID、业务数据、版权和开源许可保持原有含义。

## 5. 构建、部署与验收

在安装镜像构建前完成品牌修改；已部署时构建新镜像并更新同版本的网页与 backend／frontend，不能只临时向运行容器复制图片。确保企业资源进入构建上下文和静态资源目录，按该版本执行 `bench build --app tradept_core` 等构建步骤，并验证资源 HTTP 返回成功。

记录上游标签、提交及企业品牌补丁／资源的 SHA256；品牌修改后的构建清单与上游原始清单分别保留。按真实修改重新生成企业交付清单，不把原始源码哈希伪装成修改后的哈希。

你完成实际页面检查，并留下预览或截图：

| 检查 | 通过条件 |
|---|---|
| 登录页与侧栏 | 桌面和窄屏下显示完整、清晰，比例正确，无切字、拉伸和溢出 |
| 浅色／深色 | 手动切换及跟随系统均正确，文字可辨，品牌颜色符合处理方案 |
| 原生后台 | 导航、实际存在的站点 banner／footer 和图标使用企业版本，刷新不会被脚本恢复成旧图 |
| 浏览器与缓存 | favicon／触屏图标正确，刷新及新会话不出现旧图或资源 404 |
| 重建与升级 | 容器重建后仍存在，交接记录包含资源、补丁和恢复方法 |

给主人展示替换效果；有具体问题就修复后再检查。只确认文件存在、设置保存或图片上传不能算替换完成。交接表写“保留原 logo”或“已替换并完成浅／深色验收”，并记录素材和修改位置。没有企业素材或主人选择不替换时，这一步不阻止部署。
