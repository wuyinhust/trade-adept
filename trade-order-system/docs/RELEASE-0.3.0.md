# Tradept 0.3.0 企业管理阶段验收

日期：2026-10-13。版本按新增业务能力递增中段，历史 `v0.2.0` 标签和运行包保留。

本版本合并独立管理中心、六步新企业初始化引导和运行时实时汇率，继续使用独立 Frappe/ERPNext 企业数据库。完整产品方向和“原 Grandware 的需求可以用 Tradept 满足”的逐项交付标准见 [产品方案](Tradept-完整产品方案.md)。本阶段交付企业管理和初始化，完整业务闭环继续按该方案推进。

## 可使用的功能

- 企业管理员维护企业资料、公司订单前缀、上下级部门、负责人和可访问公司范围。
- 创建成员、分配岗位和公司、停用与恢复账号、重置临时密码；拒绝覆盖已有账号，保护当前管理员的管理入口。
- 管理角色的操作权限、可见页面和本人、部门、企业数据范围；编辑保留原有模块限制。
- 配置 ERPNext 原生 Email Account 的服务器、加密方式、默认收发邮箱、替代登录名和成员授权；支持先保存为“待填写密码”，密码不返回浏览器。
- 新企业管理员首次登录进入初始化，保存配置和步骤进度处于同一事务；已有企业跳过初始化，日常管理不重开引导。
- 实时汇率依上游发布时间缓存，失败后重试；正式单据与历史继续使用冻结汇率，财务写入验证每企业独立网关签名。
- `/api/version` 只返回运行版本、Git 提交与源码清单哈希；业务数据和私有配置继续受授权保护。

公司主体已建立后，名称、国家、法域和本位币不可直接修改；需要更名或账务迁移时使用单独受核对的流程。该限制在界面说明，防止工作台和原生账务主体不一致。

## 环境升级

升级前对云端两个站点分别产生 SQL、公开文件、私有文件和配置备份，共八份；使用当前云库迁移原生应用。源码包、原生镜像、Git 标签、CI 和 HTTPS 实际运行标识各自核对；线上实测结果记录在本轮独立部署回执与 Release 正文。

沿用现有测试主机及两套企业数据库，保持同机其他服务和数据库、Redis 持久卷。部署包包含已冻结源码与 vendor；凭据、客户导出、数据库和依赖目录不进入 Git 或镜像。

企业邮箱的实际 SMTP/IMAP 连接与对外收发，需要配置企业真实邮箱凭据后验证。本轮已验证原生配置、授权、默认切换和加密保存，没有发送外部邮件。普通员工岗位导览、邮件队列状态界面和完整报价到收付款流程继续按产品方案实施。
