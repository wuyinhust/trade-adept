# Tradept 0.4.0 统一发布验收清单

本文件定义 0.4.0 统一候选的验收门槛。实际冻结、提交、镜像和发布结果以独立回执及 `/api/version` 为准。目标站点：https://tradept-test.szkuohu.com/。

本次统一包含“完善”“梳理 ERPNext 登录方案”和“开发”的新代码。功能升级预计使用 0.4.0，最终以合并内容确认。线上 0.3.0 和回滚资料继续保留。

用户已明确选择私有启动方式：发布全部新代码，不保留演示账号；管理员账号在部署时生成，企业邮箱登录在私有部署初始化后启用。公网只路由 Grandware 私有工作区。原 Grandware、Example 的演示工作台账号停用并撤销旧会话和 API 凭据，两个原生 Administrator 的已知旧凭据轮换；历史成员资料、归属、公司和业务记录保留。新凭据只进入受保护的私有文件，不进入源码、Git 或聊天。

**交付标准：原 Grandware 的需求可以用 Tradept 满足。** 必须以原需求和真实任务逐项验收，不能以菜单出现、接口存在或单元测试通过替代。原始金额、电话和历史参考单据保持可核对，不把历史订单重放成新账务。

## 执行顺序

1. 各负责人完成代码，交付 LOGIN_READY、FINANCE_READY、BUSINESS_READY 和文件哈希；未满足项逐项关闭。
2. root 设置统一版本，校验复制前后清单，建立不可变验收候选。后续构建和测试只使用候选，不从持续变化的共享目录打包。
3. 同一完整镜像在隔离站点运行真实登录、管理、Grandware四公司业务、财务、权限及并发验收。任何必要修复均建立新候选，不能把旧回执贴到新源码。
4. 完整验收通过后统一提交 Git、准备备份与回滚，部署到指定站点，迁移两数据库和明确授权的财务角色模板。
5. 核对线上版本、Git commit、源码清单、镜像、静态资源和实际登录/业务。全部合格后发布版本及交付回执。

本清单持续记录实际结果；尚未验收的行不能视为已交付。
