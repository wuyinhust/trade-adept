# 业务需求与实现审查

日期：2026-10-11。范围：原始需求 Markdown、原始 ZIP 的 v56 业务模块、本地界面重订后的实现，以及父审查任务获得的线上公开 v40 静态代码。未访问客户数据库、未修改线上数据。本文件的原缺陷行号指本轮修改前的 v56/UI v57 审查基线；修复后通过函数名定位。

## 先明确版本与业务口径

需求文档的架构章节是作者描述，不能直接视为代码满足要求的证明。文档同时记录私有诉求和当时实现惯例，通用产品应把 Grandware 行为作为一个租户模板，业务数据必须带租户和法人主体；不能让“自己创建始终可见”的兼容兜底穿透租户边界。

线上公开脚本与本地 ZIP 存在重要版本差异：父审查任务下载到 `/private/tmp/trade-online-review` 的线上入口为 v40，国内利润使用 `收入USD×汇率−工厂成本RMB−货代费RMB−其他费RMB+(工厂成本/1.13)×退税率/100`。本地 v56 `exchange.js` 将同一组字段解释为 USD 费用，固定 13% 退税。界面又沿用 v40 的 RMB/退税率标签。故不能把线上客户历史字段按 v56 语义重新计算或迁移。

公式应具备可追溯的版本、法人配置、字段币种、适用日期和订单汇率快照。Grandware 的 `insuranceCostUSD` 历史字段名虽然含 USD，实际可能保存退税率；必须按来源版本识别，不能单凭字段后缀转换。系统应保存原始值及原公式版本，提供预览对账后再迁移。

## 重点缺陷与可复现影响

### P0：会损坏业务数据或改变利润判断

1. **单证员修改备注会清空工厂及成本。** `orders.js:721-738` 不渲染工厂区；`793` 无条件调用 `updateFactoryCost`，`930-935` 零个金额求和置零隐藏成本；`974-1045` 仍发送空工厂、空产品、零数量、空预计出运/实际出运日期、零工厂付款。复现：已有多工厂订单由单证员打开编辑，仅改备注保存。修复：只提交渲染且授权的字段，缺失部分不作为空值；数据层与服务器拒绝未授权财务字段，角色受限更新不重算隐藏金额。
2. **同单号等于同记录 id。** `data.js:1055-1066/1086` 无跨用户原子分配和唯一检查，两个浏览器同时预览第一单都会获得同号；两个香港法人也可能各自得到相同 OP 前缀单号。合并以 id 为键时一条订单消失。独立 UUID 解决身份碰撞；同法人单号仍必须由数据库唯一约束解决并发，不应把本地检查当成最终保证。
3. **国内利润的字段语义冲突。** 本地 `orders.js:375-376/464-481` 将费用标成 RMB 和退税率%，`exchange.js:40-44` 却将三项作为 USD 费用换算、且固定退税 13%。隔离内存复现：收入 USD 10,000、成本 RMB 50,000、汇率 7.25、货代费 RMB 1,000、退税率 13、其他 RMB 200；本地结果 19,457.96，按界面/线上 v40 为 27,052.21，差额 −7,594.25。必须用来源公式版本解释，不得推断旧客户数据含义。
4. **CNY 与 USD 合并成一个币种。** 管理员/财务 `filterByCompany` 跳过当前公司，`getProfitAnalysis` 在客户、类别、月份聚合时相加混币，Profit 再按当前公司标 RMB/USD。隔离复现：同客户国内收入 CNY 1,000、香港收入 USD 100，被统计为“1,100”并标一个币种；成本与利润同样混合。需要币种分组或显式报告币种换算。

### P1：流程结果失真与通用产品缺口

- **模板不能正常导入。** `order-import.js:80-88` 客户别名先匹配 `客户订单号`，覆盖客户列。模板真实顺序 `[客户,客户订单号,订单金额(USD)]`，测试 Demo Customer/PO-DEMO/1000 后报“客户 PO-DEMO 未找到”。本轮改为完整别名优先、重复/歧义列整批拒绝；同名客户多匹配也拒绝。
- **导入“成功”不代表已创建/已持久化。** `205-206` 返回 null 仍计成功，239-245 成功 UI 在 flush 前出现。本轮仅计数实际创建的记录，数据库提交完成才显示成功；失败展示待保存状态，重试提交同一批记录并暂时禁用文件选择，避免重新创建。跨行事务/冲突定位仍需新 API 支持。
- **联系人重新分配 id。** `customers.js:623-632` 每次收集都生成新 id。按 id 并集的云合并会把编辑当新增、把删除当缺席而非删除。本轮保留稳定 id，删除由版本化数组替换表达；旧 Cloud 适配不能再自行并集。
- **物流提前报保存成功。** `shipping.js:283-289` flush 未完成先关闭并成功提示，失败不保留编辑窗口。已改 await 成功才关闭，失败继续保留窗口；不存在关联订单不会崩溃。
- **订单空号自动生成无效。** `data.js:1077` 先 required 验证，1090 才生成，表单还 required。本轮改为校验前生成，表单允许新建时留空，编辑号仍必填。
- **汇率自动刷新覆盖人工核算。** 每小时把所有固定国内法人汇率统一改写，随后重算历史订单；关闭仅本会话有效。已确认是通用产品重大差距，需按法人持久化设置和历史/预算利润区分。
- **单笔预览错误使用当前法人。** 管理员在当前国内账套编辑香港订单，表单按订单标签为 USD，但 `calcProfit:953` 用当前公司核算。本轮给表单绑定订单 companyId，预览使用该法人。
- **收款仅累计总数，无流水。** `orders.js:1121-1126` 将本次数加到当前总额，没有收款事件 id、币种/日期/核销、幂等键或修订号；负数/超收没有业务规则。应记录收款流水和余额，不只改汇总字段。
- **状态时间线缺真实时间。** `shipping.js:160/168/176/184` 用订单日期或同一 ETD 代替各事件。需要状态变更事件和独立实际时间；未发生事件不得显示为完成。

## 修复边界与验收

本轮补丁处理可明确判定的数据损坏、身份、表头、联系人及成功提示问题；数据库级并发和权限由服务器实现并以端到端并发测试证明。代码中的本地权限 guard 只是便捷保护，不能替代服务器鉴权。

利润页本轮也已修复：增加结算币种选择，分别显示 CNY/USD 的卡片、图表、表格和导出；读取共享的 `Exchange.getOrderFinancials` 解释每条订单公式。报表构建新对象，不写回原订单。Grandware v40 的退税率不再当保险费计入成本，导出新增结算币种、公式版本和退税金额。旧 `DB.getProfitAnalysis` 的混币汇总已从此页面移除，其他调用方不得沿用旧聚合值。

新建单号优先使用法人配置的 `orderPrefix`，其余币种判断读取法人配置；不依赖固定四公司 id。Excel 模板按公式政策给出费用币种及退税率表头，明确币种冲突会拒绝导入。订单导出每行携带法人、结算币种、公式政策、费用币种及原始字段单位；受限角色不导出财务列。新订单/客户保存失败后继续使用同一待提交记录 id，重试不会新增重复记录。

自动化回归位于 `tests/business-review.test.js`：UUID/跨法人同号、软删号保留、自动生成、历史 id 不变、金额校验、模板 PO 分列、歧义/费用币种冲突拒绝、导入 null 不算成功、待保存/失败同批重试、联系人 id 稳定及删除、单证员备注编辑保全生产/财务资料、新订单/客户失败重试、物流保存失败/等待成功、导出单位和字段权限、混合币种分开统计且不修改原数据。测试使用假数据和模拟持久化，无外部数据库请求。本轮此前业务与数据层定向测试通过 171 项；导入持久化新增 2 项，最终结果以主审查任务全套测试记录为准。

本轮未完成的业务范围仍包括：需求 3.3.1 的业务员筛选、HK 海外港口必填的统一服务端规则、产品类别从工厂名称改为业务分类、多工厂与多联系人完整 Excel 往返、可编辑工作表与批量草稿、收款流水、真实状态事件时间、历史公式对账迁移。它们不能由现有修复或截图视为完成。

验收通用产品还须覆盖：Grandware 四法人模板；第二租户同名法人/单号完全隔离；每个角色直接 URL、查询及导出均不泄露；同记录同时编辑返回冲突并保留双方；同单号并发创建一条成功另一条明确拒绝；联系人删除跨端同步不复活；恢复单条历史不覆盖别的行；不同币种不得无依据相加；不同部署后端保持同一行为；真实历史与线上 v40 对账一致。
