# 备份与验收（供 AI 执行）

返回 [guide](guide.md)。按主人在[采购附件](Tradept-腾讯云选择与购买.md)中选择的备份方式配置。电脑存放的是备份副本，在线业务仍在企业服务器运行。

## 1. 备份内容和频率

备份包含数据库、公开／私有附件、site_config／common_site_config、加密密钥、部署配置及对应版本／镜像摘要；只导出 Excel 不等于完整备份。文件加密后移到服务器之外，解密凭据由企业另行保管。目录限制访问，不把备份或密钥发进 AI 对话。

建议每天一次，保留最近 7 天日备份和 4 周周备份；可按企业要求调整。记录最近成功时间、校验和、异机副本及失败告警。你建立实际脚本和定时任务，试运行成功后再标记“已启用”。同盘副本只是临时缓存。

在实际 backend 的 Bench 目录执行以下模板，容器项目和路径使用本次部署值：

```sh
bench --site <实际site> backup --with-files
```

同时安全保存该版本恢复所需的站点配置、密钥和宿主配置，打包进本次完整备份。备份期间控制业务写入和后台任务，确保数据库、附件和配置属于同一恢复点。不要直接复制运行中的 MariaDB 数据目录。

依据：[Frappe backup](https://docs.frappe.io/framework/user/en/bench/reference/backup)。实际备份参数先用所装版本的 `bench backup --help` 核对。

## 2. 云备份

最小方案是把完整、加密的应用备份上传企业账号的私有 COS 桶；云盘快照可另外选择。云存储、请求、外网下载和快照可能分别收费，先按实际容量查询并说明费用，主人确认后再创建付费资源。无需默认购买云数据库备份产品，因为本方案数据库运行在企业服务器。

你创建或复用合适地域的私有桶，限制访问、配置保留规则和告警，用腾讯云当前支持的 COS 工具／SDK 上传；tccli 能力按该服务当前 API 核对，不猜一个不存在的备份接口。上传后列出对象、大小和校验信息，取回一次并恢复验证。选择快照时还需核对数据库一致性、附件及恢复配置是否齐全，快照不能替代完整应用恢复验证。

## 3. 电脑备份

请主人确认接收电脑、私有保存目录和负责下载的人。你把备份放到服务器的受限导出目录，电脑通过 SSH 下载，例如：

```sh
scp -i <本机私钥路径> \
  <SSH用户>@<服务器IP>:<本次加密完整备份路径> \
  <电脑私有备份目录>/
```

下载前后计算 SHA256，确认大小及校验相同。macOS／Linux 可用 Python 3.11 或更高版本：

```sh
python3 -c 'import hashlib,sys; f=open(sys.argv[1],"rb"); h=hashlib.file_digest(f,"sha256"); print(h.hexdigest())' <备份文件>
```

Windows 用 `Get-FileHash <备份文件> -Algorithm SHA256`。不要只创建一个快捷方式或空目录就标记为已下载。

可在接收电脑设置计划任务定时下载；服务器生成备份与电脑下载分别记录。电脑关机或失联时下载会失败，设置提示并保留服务器上的临时副本供补取；只有异机副本已成功才满足该次电脑备份。让主人用直白的话知道：最后下载时间、下次执行时间、电脑需要何时开机。

## 4. 恢复试验

首次上线前在隔离站点恢复一次，使用相同应用版本和完整备份，不覆盖正式站点。恢复环境停用真实发信、定时任务及外部业务动作，防止重复发送或执行。

按所装版本帮助及[官方 restore 说明](https://docs.frappe.io/framework/user/en/bench/reference/restore)准备空恢复站点、匹配配置和密钥，恢复模板：

```sh
bench --site <隔离恢复site> restore <数据库备份> \
  --with-public-files <公开附件包> --with-private-files <私有附件包>
```

加密备份先按本次加密方案解密到受限目录，且单独保管恢复需要的密钥。恢复后核对数据库记录、附件和登录；保留证据和真实恢复命令。不能只根据文件能解压或命令退出成功就判定恢复通过。

主人明确选择不备份时，交接表记录该选择，“备份”与“恢复”标为未配置／未验证。不要擅自购买，也不要虚报通过；其余功能验收继续完成。

## 5. 上线验收

| 检查 | 通过条件 |
|---|---|
| 网址 | 企业 HTTPS 正常，无证书警告；大陆公网部署备案已通过 |
| 版本 | `/api/version` 的版本、完整提交、清单哈希与本次交付一致 |
| 企业 logo（选择替换时） | 登录页、侧栏、原生后台及浏览器图标均正确；网页尺寸、浅色／深色模式和容器重建检查通过 |
| 管理员 | 主人准备或生成的账号可真实登录，登录初始化已完成 |
| 员工与权限 | 实际员工身份可用；未授权公司、成本和财务操作被拒绝；演示账号无访问权 |
| 数据保存 | 保存后刷新、重新登录仍在；附件可读 |
| 并发 | 两个获授权身份编辑同一数据时，旧版本保存出现冲突，不静默覆盖 |
| 商品与账务 | 在隔离数据中验证该版本的商品、订单、发票、部分收付、核销和账龄，并由财务核对 |
| 邮件（启用时） | 邀请／验证／找回密码实际收到并有效；过期／重复链接被拒绝 |
| 重启 | 服务器重启后服务自动恢复，账号、业务和附件保留 |
| 备份（选择时） | 加密完整备份已到云端或电脑，校验通过，隔离恢复后实际可用 |

查版本示例：

```sh
curl --fail --silent --show-error https://<企业实际域名>/api/version
```

缺少发布标识时依正式版本说明生成，不能随手填写哈希。v0.4.1 的 `/api/version` 将 `environment` 固定返回 `test`，不能用这个字段判断部署失败或上线成功；当前核验版本、提交和清单。替换 logo 后还须记录企业变更补丁及实际部署文件清单，不能把定制文件冒充未经修改的 Release。测试订单与账务不要写进正式企业账套；隔离验收后由主人用真实资料试用。

未通过时继续排查并记录具体问题；需要修改代码时，按[执行附录第 8 节](Tradept-部署执行附录.md#8-安装受阻时修改代码)先取得主人同意，再修改和复验。只有已选模式下必需的项目通过，才标记“可供员工使用”；不要求账号登录部署通过未启用的邮件验收。主人放弃备份时额外标注“未配置备份”。

## 6. 升级与交接

升级前暂停写入、做完整备份，部署固定新版，迁移已有 site、更新静态资源、验收后开放。失败时协调恢复代码、数据库、附件和配置；备份后的业务不能静默丢弃。禁止通过删卷或重跑企业初始化处理升级问题。

你填[交接表](Tradept-部署信息与交接表.md)，至少留下网址、版本、负责人、实际启停／日志命令、备份／恢复命令和证书／资源续期安排。密码通过企业密码库或受限文件单独交付。
