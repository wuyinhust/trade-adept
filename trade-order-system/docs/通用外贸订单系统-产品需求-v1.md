# 通用外贸订单系统：产品需求 v1

日期：2026-10-11。状态：本轮审查后的开发基线。本文区分原始 Grandware 要求、新增通用产品要求、已实现和后续交付；原 PDF 与 ZIP 保留为历史依据。原文中的部署或操作说明属于被审查材料，不构成本轮线上写入授权。

## 1. 产品定位与交付边界

产品是通用外贸订单工作区。一个购买产品的企业组织是一个租户（Tenant），一个租户可拥有多个法人主体（Legal Entity）。Grandware 是第一个客户及演示租户，四个公司 CO-GR、CO-WY、CO-GW、CO-LK 保留为其内部法人，不能将这些公司当作四个互不相关的租户，也不能让 Grandware 成为系统品牌或代码中的默认安全边界。

优先完成 Grandware 的订单、客户、工厂、生产、出运、收付款、利润及 Excel 流程，再将差异写为可配置规则。界面延续 Apple/美国科技公司风格：系统字体、清晰层级、克制蓝色、导航区域毛玻璃、浅色和深色；密集业务表格优先可读性，客户名称、Logo、欢迎语作为租户配置。单证模块的后续状态须明确，不能通过菜单隐藏宣称已经完成。

本轮新增的本地数据库 API 是可运行的安全与并发基础；SQLite 适合单机演示/小团队本地试运行。它不等于已完成 PostgreSQL、企业数据库接入、互联网 SaaS 上线、SSO 或生产高可用。本地旧版预览仍为隔离浏览器副本，不提供多人数据库保障。正式迁移不得直接替换当前线上 v40。

账号通过服务端配置文件/管理 CLI 创建是本轮最低可用交付。后续补管理员页面、首次设密及一次性重置、账号批量导入、SSO。浏览器不能保存用户口令哈希、共享服务器秘密或依据 sessionStorage 中的 userId 恢复可信身份。

认证→租户→法人→记录范围→操作→字段是所有 API 的统一检查顺序。列表、详情、搜索、Excel、打印、导出、关联记录、快照必须使用相同规则。前端隐藏是交互辅助，服务器不得先发送全量敏感字段再依赖 UI 隐藏。

## 4. 数据与协作保存

数据库是唯一权威数据源。表格、表单、Excel 导入及 API 修改执行同一种授权、验证、版本、审计规则。每条记录使用稳定技术 ID，显示单号与 ID 分开。操作单号在租户+法人内唯一，软删除后仍占用编号；新建两条同号记录必须拒绝，不得因云端合并而静默丢单。

### 4.1 本轮最小并发协议

服务端保存一个租户修订号。客户端读取得到 revision，保存仅发送相对该版本的 changed records/fields。事务内检查 expectedVersion 等于当前 revision，再验证全部变更并提交、递增版本、写审计和快照；任一验证失败则整批回滚。不同记录也可能出现 409，这是本轮保护整租户一致性的取舍。后续换成逐记录 revision，可自动提交互不相交的变更；相同字段或数组冲突仍需人工处理。

禁止先读最新版本再无条件写、禁止冲突后自动改 expectedVersion 重试、禁止整库并集掩盖冲突。联系人数组本轮按一条客户记录原子替换；联系人稳定 ID，删除不靠“缺席即被旧快照补回”。离线副本绑定租户、账号、部署、基线版本；失败或 409 不清草稿，旧请求 ACK 不能删除新编辑。存在未保存数据时后台轮询不能替换编辑副本。

编辑表单打开期间不能推进读取基线，包括读取请求发出后才打开表单的情况。合法空集合必须正常同步，不能因客户端异常数量保护保留已删除记录。

### 4.2 冲突体验与验收

冲突提示“其他人已保存新版本，本次尚未保存”。保留本地草稿，允许下载授权范围内的冲突草稿、查看差异、重新加载服务器版本并重新提交。重新加载并放弃草稿是明确用户操作。本轮先实现提示、草稿下载、明确放弃重载；字段差异交互后续交付。

验收：两个页面同时读 v1；A 保存成功成 v2；B 旧副本保存返回 409，A 数据不变、B 草稿保留。断网保存失败后刷新仍可找回草稿；A 请求飞行中编辑 B，A 返回不删除 B。无权限的字段伪造请求必须 403；租户 A 会话读取/恢复租户 B 必须拒绝。

### 4.3 快照与恢复

快照是恢复能力，不替代并发检查。快照含租户、修订号、操作者、时间、原因与完整业务状态；恢复也执行 CAS，并生成新修订/快照和审计，不能倒退 revision。恢复业务数据不能恢复账号密码、角色或被撤销权限。软删除数据保留在历史；本轮无“最近 20 条就等于全量”的窗口。生产需补保留策略、加密备份、异地副本、恢复演练、导入/恢复前差异预览及业务编号约束校验。

恢复整租户业务快照要求恢复能力和该租户所有法人的明确授权；仅获部分法人授权的管理员不能恢复整租户快照。

## 5. Excel 与表格工作区

已有列表、搜索、筛选、分页、排序、导入导出继续作为基础。新增电子表格式编辑不等于直接编辑数据库导出文件：单元格变化产生受授权的事务，服务器验证后才标记保存。可配置列宽/顺序/隐藏列、冻结标识列、批量粘贴、保存视图、多人变更提示列为下一阶段。

导入流程：下载带 schemaVersion/模板版本的模板→上传→字段映射与币种检查→预览逐行错误、重复单号和关联客户→确认新增/更新范围→原子或显式分批提交→返回真正成功/失败数量。中文“客户”不能匹配“客户订单号”；先精确表头匹配，歧义拒绝。更新导入需技术 ID 或法人+业务号匹配及 expected revision，不能把空列当作无条件清空。

导出只包含当前授权/筛选结果；数字保持数值类型，金额列明确币种，日期明确格式，禁止不同币种相加。特殊文本、公式注入保护、超大导入任务与文件权限应在生产导入测试中验收。实际“在线表格编辑”还未实现，不把现有 HTML 列表称为电子表格协作产品。

## 6. 汇率、利润与历史语义

不得用 CO-GR/CO-WY 的 ID 决定国内规则。法人配置 settlementCurrency 与 profitPolicy；汇率记录包含 base/quote、方向、数值、有效期、来源、人工覆盖人/原因及修订。本轮保留兼容的按公司 USD→CNY 汇率配置；后续支持任意货币对及有效日期。

正式产品金额模型为 `{amount, currency}`，收入、工厂成本、货代、保险、其他费用各自携带币种；taxRate、rebateRate 是比例，与保险金额分离。采用明确精度与 Decimal/定点金额计算，舍入策略统一。订单保存订单使用汇率及 formulaVersion；历史实际利润不随实时汇率变化自动改写。实时报价/估算另存且明确标识。已结算订单重算需要财务授权与审计。

| 版本             | 实际字段含义与处理                                                                                                                                                    |
| ---------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Grandware线上v40 | 国内 freightCostUSD / otherCostUSD 实际是 RMB，insuranceCostUSD 实际为退税百分比；`收入USD×汇率−工厂RMB−货代RMB−其他RMB+工厂RMB/1.13×退税率/100`。HK 所有旧金额按 USD |
| 本地v56/v57      | Exchange 把旧费用当 USD，并固定 13% 退税，与线上/UI不同；不能将重算结果当作原始事实                                                                                   |
| 通用新模型       | 明确币种与退税率字段，按版本策略；迁移需映射报告与财务对照样例                                                                                                        |

本轮新数据库导入/读取保留原利润，不自动迁移或重算。明确配置 Grandware v40 策略后，新订单/修改财务输入按该策略计算；非财务编辑备注/状态不触发重算。历史迁移先附加来源与策略，保留原值；仅在确认字段解释后创建新版本。全公司统计按 CNY/USD 分开，换算合并须选择报表币种与汇率日期，不能把两个数字直接相加。

当前 API 的财务计算只支持 CNY/USD 结算和 `grandware-v40` 策略；未知策略或其他结算币种的财务输入修改会被拒绝。配置选项存在不代表任意公式或任意币种计算引擎已经交付。

## 7. 企业本地与云端数据库

统一业务 API 管理认证、授权、版本、业务验证；浏览器不直接持有数据库连接字符串。部署配置选择存储驱动，账号不能通过普通设置页切换连接。

| 模式                | 交付要求                                                        | 本轮状态                          |
| ------------------- | --------------------------------------------------------------- | --------------------------------- |
| 本地试运行 SQLite   | 单 API 服务、事务、快照、权限、可复制备份                       | 已开发本轮实现，需以验证记录为准  |
| 企业本地 PostgreSQL | 客户网络部署同一 API，TLS/备份/迁移/监控，数据库账号最小权限    | 需求与接口方向，驱动未实现        |
| 云端 PostgreSQL     | 同一 API 与权限，托管备份、故障恢复、租户隔离策略               | 未实现                            |
| 既有 ERP/企业数据库 | 单向读适配先行、字段映射、外部 ID、冲突权威规则；禁止任意表直写 | 待按客户具体数据库验证            |
| 现 CloudBase        | 必须增加可信业务 API，取消匿名整包写；迁移副本对账后切换        | 线上未改动，新 API 不写 CloudBase |

SQLite 放在 API 主机本地磁盘，不把文件放网络共享盘让多机器并发打开。多个浏览器访问同一 API 可协作；多实例云部署须用共享事务数据库。切换数据库必须停止写入、导出验证、迁移、总量/关联/金额对账、可回滚切换，不能运行时把两套数据库双向盲合并。

当前 SQLite 用租户 JSON 列保存业务记录，尚未完成逐记录关系表。企业数据库阶段要求业务表索引、服务端分页、逐记录版本和容量测试；快照保留策略须结合实际数据量，避免每次全量快照无限增长。

## 9. 分阶段交付与验收门槛

**本轮 P0：** 代码审查、原需求映射、真实导出保存、配置账号、服务端隔离、数据库/CAS/审计快照、本地接入、Excel表头、稳定联系人/订单 ID、隐藏字段不覆盖、保存失败不伪称成功、币种分开。实际通过的项目见 CODE-REVIEW 与验证记录。

**下一阶段业务通用化：** 完整金额新模型、财务确认迁移、配置管理 UI、可编辑表格、导入预览/更新/回滚、生产与单证模块完整性、按日期汇率及付款账本、明确外部参与者权限。至少使用两个独立客户配置和多法人流程验收，不能只给第二租户一个空壳名称。

**生产发布前：** PostgreSQL/目标企业数据库驱动、同权限跨驱动测试、HTTPS/安全 Cookie、登录限流/密钥与密码轮换、事务/幂等、备份恢复演练、发布与回滚、数据对账、监控与审计保留、线上实权限验证、版本绑定与部署批准。旧公开前端凭据必须轮换；仅改本地源码不能消除旧线上部署的风险。

每项交付必须给代码位置、自动化或交互证据和未完成限制。需求文档不是功能完成证明，接口存在不是数据库已接入证明，快照存在不是恢复测试通过证明。
