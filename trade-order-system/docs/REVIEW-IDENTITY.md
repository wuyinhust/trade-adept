# 账号、权限与企业隔离审查

日期：2026-10-11。审查基线：v56 归档源码及 UI-v1 本地实现。此文记录修复前证据；后续实现与验证见 `server/README.md`。

审查仅读取本地源码与需求 Markdown，未访问生产数据库，未修改生产权限。动态复现采用 Node 纯内存 session/localStorage 与 mocked CloudBase SDK，不调用真实云函数。本文不记录口令、哈希或真实业务记录。

## P0

1. **浏览器会话可伪造。** `js/auth.js:139-148` 从未签名 sessionStorage 的 userId 恢复身份；本地登录 `:193-204` 比较前端公开用户表。纯内存设置现有管理员 ID 后，`Auth.init()` 返回 true 且角色 admin。前端锁定状态同样可清除。需要服务端账号验证和随机会话，客户端不得决定身份。
2. **customLogin 可重放公开哈希。** `js/auth.js:16-110` 公开固定密码哈希；`js/cloud.js:406-413` 将哈希直接作为口令发送；`cloudfunctions/customLogin/index.js:63-104` 比较相同哈希后签票据。mock SDK 复现 HTTP 200/admin。浏览器共享密钥不能补救；服务端保管独立加盐口令摘要，旧公开凭据轮换。
3. **匿名整包数据库访问没有业务授权。** `js/cloud.js:299-339` 自定义登录失败后降级匿名；`:495-507` 查询没有 tenant/company/actor；`:850-867` 写整库。`:19-35` 推荐安全规则只检查 dataType 或存在 auth，未核验仓库外实际线上规则。应禁止生产匿名降级，业务 API 验证租户、法人、记录操作和敏感字段；仅允许数据库访问服务端。
4. **CRUD 没有对象权限。** `js/data.js:1050-1052,1101-1138,1180-1182,1221-1244,1395-1401,1442-1469` 读取/修改只按 ID。finance 的 `canDeleteOrder=false`，但纯内存 `DB.deleteOrder` 实际标记删除。编辑/收款入口 `js/orders.js:565-567,1077-1126` 同样接受已加载任意 ID。按钮隐藏不能替代后端授权。

- **团队列表/详情不一致。** `js/auth.js:360-375` 允许团队 createdBy；`:379-384,398-408,439-447` 仍只看业务员 ID。经理可见团队单证员订单列表，但详情、客户、出运都不可见；纯内存已复现。用统一记录谓词。
- **自己创建的跨主体记录被第一步丢弃。** `js/data.js:765-779` 当前公司过滤先于 creator 兜底，需求 `:161-176` 要求始终可见。复现其他法人自建订单：列表0，详情允许。通用租户硬边界不能被 creator 绕过；跨法人历史数据用显式修复/授权。
- **设置危险操作缺权限。** manager 可到 settings（`js/auth.js:434-435`）；`js/settings.js:164-186,266-319,497-517` 导出全 DB、导入/清空、切换连接。需操作级 backup/export/import/restore/configure 能力；禁止普通经理导出原始全库。
- **恢复缓存未绑定租户与连接。** `js/data.js:531-590` 共用 gw_local_backup 并自动传播删除；`js/settings.js:444-455` 切连接后初始化恢复。未来多企业可能串入数据/墓碑。缓存绑定 tenant/deployment/actor/schema，恢复显式校验，不跨环境自动合并。
- **缺配置默认放行。** `js/auth.js:315-317` 无团队/缺团队返回全部公司。新配置账号应 fail closed。

## 产品模型建议

- Tenant 是一个购买产品的企业组织；Grandware 为一个租户实例。LegalEntity 是租户下法人主体，两者不混用。
- 账号由管理员配置/导入，无公开注册；服务器存口令摘要。角色为可配置操作能力+范围模板，Grandware 预置五角色。
- 授权顺序：服务端会话 → tenant → legal entity → self/team/tenant scope → 操作 → 字段。缺主体/未知归属旧记录普通角色拒绝。
- DB 放在业务服务层后，提供本地 SQLite/未来企业 SQL/云 SQL 适配；浏览器只能访问业务 API。
- 逐记录 patch + 原子 CAS，409 不自动覆盖；审计与快照恢复创建新 revision，同样校验 expectedVersion、当前权限和租户来源。

## 实际修复边界

新 `server/` 本地业务服务实现可信会话、配置账号、逐记录权限、SQLite revision、审计与快照，默认仅监听 127.0.0.1。原 CloudBase 实现不用于此本地接口。部署到公网前需要 HTTPS、正式配置凭据、运维备份与所选企业数据库适配；当前实现不能声明这些已经交付。

## 修复后验证记录

2026-10-11：`python3 -m unittest server.tests.test_service -v`，42 项通过，耗时 6.910 秒。测试使用两虚构租户、临时私有 SQLite 和真实本机 HTTP；未连接生产。登录、Cookie、禁用账号、密码轮换/过期、CSRF/Host、静态私有文件拒绝和并发写入均实际执行。两个相同 revision 的 HTTP 保存结果为一个 200、一个 409；成功整批提交，失败整批回滚。

新增本地服务也接受了独立代理使用合成数据的第二轮审查。以下问题在新服务实现阶段发现，已修复并补测试：

| 复现条件 | 修复与验证 |
| --- | --- |
| 普通账号重复 factoryId，复制隐藏成本 | 拒绝重复条目；数据库 revision、成本与历史利润不变 |
| 含隐藏利润对象被替换为 null/字符串 | 递归保护原容器类型；返回 403 并保留原值 |
| 任意嵌套 factories.details.bankAccount/cost 修改 | 递归字段校验；省略隐藏嵌套字段时保留原值 |
| 未知财务数组重排，按 index 挂错金额 | 普通账号拒绝修改未知保护数组；显式 factories 按唯一 factoryId 匹配 |
| 同租户不同法人客户/工厂被关联到订单 | 关联对象必须同法人；订单仅改 companyId 也重查所有引用 |
| 有出运/发票的订单改法人，留下旧主体关联 | 拒绝隐式迁移，返回 409 LEGAL_ENTITY_MIGRATION_REQUIRED |
| 仅获部分法人授权的管理员恢复全租户 | 全租户恢复要求全部法人授权；未授权实体当前状态不变 |

工厂默认在账号已授权的法人内共享读取，成本和银行信息按财务权限隐藏；修改和删除继续受 self/team/tenant 范围限制。验证了普通账号能读管理员创建的同法人供应商、不能改删、不能读其他法人或其他租户供应商。readScopes 可配置，缺法人授权仍拒绝。

独立增量复核 12 个合成 SQLite 场景全部通过：11 个拒绝场景验证 payload、rates、rateMetas、revision、更新时间、审计和快照计数完全不变；双工厂公开重排成功并保持历史派生金额、各工厂隐藏成本、预付和省略的嵌套银行值。复核未修改项目文件或访问线上。

最终法人授权规则覆盖全部角色：scope=tenant 不等同授予全部主体；无显式个人 visibleCompanyIds 或明确团队主体配置的管理员同样不能读取/写入业务法人。示例 admin/finance 显式配置全部法人，测试验证无授权时列表/汇率为空并拒绝写入。

旧前端 inline onclick 中技术 ID 不能仅依赖 HTML 转义；API 新增安全字符集校验，拒绝记录 ID、联系人 ID、factoryId 中引号/反斜杠/控制符等。合成回归验证恶意 ID 不入库，之前的批次变更也回滚；原有 C001、含中文的安全编号和 UUID 可用。CLI 导入不安全技术 ID 拒绝，源件和数据库均保持不变；业务显示文本仍为自由文本，前端转义责任不变。

历史金额导入/读取、仅备注/状态变化、汇率配置和保留各工厂成本的数组重排不触发金额重算。只有原始财务输入变化才按法人配置的 grandware-v40 派生公式计算。账号配置不属于业务快照，恢复不会恢复过期口令或旧权限。

源码位置在 SMB 网络卷。实测不能依赖该卷权限缓存或 SQLite 本地锁语义；服务在创建敏感文件前显式拒绝网络运行目录，要求私有本地文件系统。实际演示运行目录由主代理配置为本机持久目录；不将数据库或随机口令文件存入归档源码。
