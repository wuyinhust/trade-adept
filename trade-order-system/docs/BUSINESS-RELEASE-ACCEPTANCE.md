# 业务发布验收：原始企业需求与通用产品需求

日期：2026-10-11。范围是订单、Excel 导入、出运及服务端业务校验。此文记录本地实现和验证；真实浏览器、完整 API、隔离 ERPNext 和 Git 发布证据由发布总记录汇总。

## 需求与交付

| 场景           | 原始 Grandware 要求                                | 通用产品要求                              | 本轮实现                                                                                                                                                                                                               |
| -------------- | -------------------------------------------------- | ----------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 非财务角色     | 业务员、单证员可创建及编辑自己的业务数据，财务保密 | 使用 API 配置的角色、权限和可见名录       | 收款金额、收款状态、成本、预付款控件及载荷按 `finance.write` 权限移除，详情与列表按 `finance.read` 展示；公开产品、数量和生产日期独立于财务卡片；列表和导出同时隐藏已屏蔽的财务状态，避免显示假的零金额                |
| 历史订单编辑   | 不破坏已有订单及核算口径                           | 只更新实际变更，保全被权限裁剪的字段      | 表单捕获初始控件值；未改动字段不提交。历史缺失生产字段，或客户/工厂不在当前可见目录时，单纯改备注不会清空生产数组，也不会按显示合计重算历史成本；客户不可见时，仅保留订单已知的当前客户/联系人选项，不扩大客户读取权限 |
| 产品类别       | 产品类别按生产产品填写                             | 产品类型与工厂名称独立                    | 新建或实际修改生产数据时，产品类别汇总去重后的产品类型；只改历史备注保留原产品类别，不自动迁移历史数据。                                                                                                               |
| Excel 管理     | 复用现有 SheetJS，匹配客户、PO、金额及公司口径     | 明确解析、预览、确认和数据库成功状态      | 解析零写入；列出有效行和错误；确认才创建及保存。取消零写入。保存失败保留同一批 ID，仅重试持久化；成功数统计实际创建且数据库确认的订单                                                                                  |
| 同法人引用     | 四个公司主体有独立归属                             | 每个引用保持租户及法人边界                | Excel 只匹配当前法人的客户，重名不猜测；出运只选当前可见法人订单。服务器另行验证关联订单、客户和工厂                                                                                                                   |
| 操作单号       | 公司前缀、年份、业务员首字母、序号                 | 使用配置前缀和名录，技术 ID 独立          | 导入预览在同一批中预留不同自动单号，不重复使用尚未写入的单号；含删除记录的单号仍占用；负责人筛选来自配置名录                                                                                                           |
| 出运创建       | 物流记录可跟踪，保留发票/操作单/港口/ETD/状态      | 有明确可用入口和稳定重试                  | 订单详情通过懒加载进入出运表单，物流页也可建立出运。一次订单仅允许一条有效出运记录；失败重试复用记录 ID。未填发票号显示“未填写”，详情标题优先使用关联操作单号                                                          |
| 港口           | 香港公司必填海外港口                               | 按法人配置决定，而非看到 USD 就判断为香港 | `jurisdiction=HK` 必填；旧 `CO-GW/CO-LK` 无配置时兼容。美国 USD 法人不被当作香港                                                                                                                                       |
| 日期及物流状态 | ETD 是预计离港，更新出运状态                       | 状态可解释、实际日期有来源                | ETD 与实际报关、装船、到港、签收日期分开。达到相应状态时要求其实际日期；时间线没有实际日期显示空缺。不会把 ETD 写成实际报关/装船/签收日期                                                                              |
| 精简物流字段   | 移除提单、箱号、船名/航次、目的港及 ETA            | 简化旧字段依赖，不制造搜索崩溃            | 订单详情移除废弃展示，搜索支持保留字段及可选的旧提单/箱号，容忍精简对象；旧数据库字段保留兼容，无自动删除迁移                                                                                                          |
| 批量状态       | 一次修改多笔订单状态                               | 不能提前显示数据库保存成功                | 所有下拉默认“不修改”，只提交选择项。等待数据库成功再关闭、清选择和显示成功；失败保留表单及选择                                                                                                                         |
| 收款           | 更新收款聚合值                                     | 重试不重复累计                            | 表单保存固定累计目标。数据库失败后重复提交相同目标，金额不会累加第二次；拒绝超出待收余额。完整付款流水和会计将复用 ERPNext                                                                                             |
| 服务端业务验证 | 必填、状态、正数量、非负费用、预付款、有效日期     | 绕过浏览器仍不能落入非法数据              | 独立 `server.validation` 提供订单及出运验证；存储事务调用并将 `ValueError` 转为 HTTP 400。原始补丁决定检查哪些字段，既有旧档只改备注不强制补齐历史必填项                                                               |

## 校验调用契约

```python
validate_order(merged_value, supplied_patch, creating, company_config)
validate_shipment(merged_value, supplied_patch, creating, company_config)
```

模块不引用 `Store` 或 HTTP，防止循环依赖。它们在合法时返回 `None`，非法时抛 `ValueError`。`Store` 在授权、字段合并和引用检查后调用；400 失败与该批次其余变更一起回滚。权限、租户、公司、关联可见性和版本冲突仍由存储层负责。

新建订单需要客户、操作单号、客户 PO、联系人、下单日期、起运港、付款条件及正订单金额。生产数组可以随后填写；填写生产行时要求产品、正整数数量、验货和出货日期。预付款不超过总额，检查实际提交的财务修改，避免公开生产编辑替用户修复其无权查看的历史成本。

## 后续边界

本轮未自行实现总账、付款凭证、银行对账或完整会计，应由隔离 ERPNext 接入阶段验收。当前收款是现有订单聚合字段的稳定重试，不将其宣传为完整会计。

Excel 模板仍是订单级创建流程，尚未实现多工作表工厂明细导入。当前出运模型是一单一条有效记录；分批出货和多个发票/装箱关联需要之后以稳定明细 ID 扩展，并结合 ERPNext 模型验收。历史费用字段名称保留兼容，金额与币种统一迁移另行执行。
