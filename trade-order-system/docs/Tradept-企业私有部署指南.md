# Tradept 企业私有部署指南

用 Kimi Code 协助部署到腾讯云，让员工通过企业自己的网址使用 Tradept。部署方式为：**一家企业、一台独立服务器、一个业务站点**；企业内可以有多个法人公司。

你负责准备账号、购买资源、填写企业资料；Kimi 负责安装、配置和检查。本文使用 `trade.example.com` 代表企业网址，请替换成真实域名。

## 1. 先确定要安装的版本

截至 **2026-10-13**，GitHub 已发布版本为 [v0.3.0](https://github.com/wuyinhust/tradept/releases/tag/v0.3.0)，提交为 `001a73c32a60a1999cd6299db9c7ebeaad8a2713`。

| 功能 | 部署时怎么处理 |
|---|---|
| 订单、客户、供应商、管理中心、公司部门、成员角色、新企业初始化、实时汇率 | 使用 0.3.0 基线，按企业资料配置并验收 |
| 销售／采购账单、收付款核销、账龄报表、细分财务权限、商品维护 | 已纳入 0.4.0 候选，统一验收及正式发布后启用 |
| 企业专属登录、部署生成管理员、邮箱白名单、邀请激活、找回密码、Tradept 品牌后台 | 已纳入 0.4.0 候选，统一验收及正式发布后启用 |

**本指南的正式交付目标是包含私有初始化、邮箱登录和新财务功能的已验收版本。0.4.0 目前尚未正式发布；现在可准备云资源，0.3.0 仅按其已有能力试用。** 部署当天核对正式 Release，不要把候选代码混入 0.3.0，也不要直接部署不断变化的 `main`。

正式部署不使用演示账号或通用默认密码。部署时生成企业专属的初始管理员，完成真实邮箱验证后停用该初始账号，改用邮箱登录。

仓库目前为私有仓库，请开发方给部署人员开通只读权限，或提供指定版本的部署包。GitHub 的源码 ZIP 不等于已装好依赖的安装包。开发方还需提供与服务器架构匹配的镜像，或可复现的构建材料；具体检查见 [Kimi 部署附录](Tradept-Kimi部署附录.md)。

## 2. 准备这张信息表

| 项目 | 填写内容 |
|---|---|
| 腾讯云账号 | 企业实名认证账号，资源归企业所有 |
| 企业网址 | 例如 `trade.example.com` |
| 服务器地域 | 本次采用上海 `ap-shanghai`；与企业数据要求相符 |
| 企业管理员 | 姓名、真实邮箱 |
| 公司资料 | 法人名称、所在国家／地区、本位币；有多个公司就分别填写 |
| 登录邮箱范围 | 企业邮箱域名、指定邮箱名单，或允许任意邮箱域名 |
| 发信邮箱 | 发件地址、SMTP 服务器、端口、加密方式；密码另行保管 |
| 运维联系人 | 手机／邮箱，用于续费、故障和备份告警 |

网站域名与邮箱是两回事。买了域名不会自动获得邮箱；可以继续使用企业已有的腾讯企业邮、Microsoft 365 等邮件服务。

可直接填写随附的 [部署信息与交接表](Tradept-部署信息与交接表.md)。真实管理员邮箱、白名单和 SMTP 可以在首次初始化时补齐；未完成邮箱验证前，系统只能做初始化配置，不能开始业务。

## 3. 购买服务器和域名

### 服务器这样选

上海小型企业的具体选型、TCCLI 实时报价及首年预算，见 [腾讯云选型与报价](Tradept-腾讯云选型与报价-上海-20261013.md)。小企业优先查看轻量活动套餐，先用自带 SSD；2 核 2 GB／99 元年套餐可作验证候选，2 核 4 GB 更有内存余量，均需实际业务验收。下方 CVM 配置供企业网络接入或扩容时选用，不是起步必选。

进入 [腾讯云 CVM 控制台](https://console.cloud.tencent.com/cvm)，选择“新建／自定义购买”。选择 CVM 时可参考以下配置：

| 选项 | 建议 |
|---|---|
| 服务器 | CVM 标准型，独立使用；不选竞价实例 |
| CPU 与内存 | **4 核 8 GB**；数据导入多、报表多时优先考虑 4 核 16 GB |
| 操作系统 | Ubuntu Server 24.04 LTS，64 位 x86_64 |
| 磁盘 | 系统盘 60 GB，加 SSD 数据盘 100 GB；数据库和附件放数据盘 |
| 网络 | 企业专用 VPC／子网，分配公网 IPv4；固定带宽可先选 5 Mbps |
| 购买方式 | 持续使用选包年包月；开启续费提醒 |
| 登录方式 | SSH 密钥，私钥由企业保管 |

这是初始容量建议，不是并发人数承诺；上线前用企业实际数据试运行。主机、带宽、磁盘、备份和域名分别可能收费，以购买页显示的总价及续费价为准。[腾讯云购买说明](https://cloud.tencent.com/document/product/213/506)

大陆地域通过公网域名提供服务，应按要求完成 ICP 备案后开放。若使用腾讯云 CVM 办理备案，当前要求包括包年包月累计至少 3 个月、备案时剩余至少 1 个月及符合要求的公网 IP。中国香港或境外服务器不适用大陆 ICP 备案，但地域选择仍须符合企业的数据管理要求。[备案资源要求](https://cloud.tencent.com/document/product/243/18908)

### 安全组这样填

安全组就是服务器的“门禁”。入站规则只开放需要的端口：

| 端口 | 允许谁访问 | 用途 |
|---|---|---|
| TCP 22 | 部署人员当前公网 IP，填写 `IP/32` | SSH 远程维护 |
| TCP 443 | 员工访问范围；需要外网办公时可设 `0.0.0.0/0` | HTTPS 网站 |
| TCP 80 | 使用 HTTP 证书验证时需公网可达 | 证书验证、跳转 HTTPS |

如果企业只允许内网或 VPN 访问，让 Kimi 配置对应的访问范围，并使用 DNS 验证申请证书。不要开放 3087、3088、3306、6379、8000、9000。出站需允许系统更新、镜像下载、DNS、校时、汇率 HTTPS 和企业 SMTP。

### 域名这样买

已有企业域名时，直接使用 `trade.企业域名` 子域名，通常不需要再购买域名。

没有域名时，进入 [腾讯云域名注册](https://dnspod.cloud.tencent.com/)，搜索合适的 `.com` 等域名，使用企业信息完成实名认证、购买并设置续费提醒。[域名注册要求](https://cloud.tencent.com/document/product/242/67281)

在域名当前使用的 DNS 服务商处添加：

| 字段 | 内容 |
|---|---|
| 主机记录 | `trade` |
| 类型 | `A` |
| 记录值 | 新服务器的公网 IPv4 |
| TTL | 默认值 |

DNS 在腾讯云管理时，使用 [DNSPod 控制台](https://console.cloud.tencent.com/cns)。已有网站和邮箱的记录保持原样；不要为新增子域名删除原记录。[解析操作说明](https://cloud.tencent.com/document/product/302/3446)

## 4. 在部署人员电脑上安装 Kimi 和 TCCLI

**Kimi Code** 可以运行安装命令；普通网页版聊天不能直接操作服务器。**TCCLI** 是腾讯云命令行工具，用于查询和管理云资源；服务器内部的软件通过 SSH 安装。

### 安装 Kimi Code

macOS／Linux，在终端执行：

```sh
curl -fsSL https://code.kimi.com/kimi-code/install.sh | bash
```

Windows，在 PowerShell 执行，并按官方说明安装 Git for Windows：

```powershell
irm https://code.kimi.com/kimi-code/install.ps1 | iex
```

重新打开终端，执行 `kimi --version`，能显示版本即安装成功。执行 `kimi`，输入 `/login`，按屏幕提示登录。使用账号支持的 Kimi Code 服务或 API 额度。[Kimi 官方安装指南](https://www.kimi.com/code/docs/kimi-code-cli/guides/getting-started)

### 安装 TCCLI

先安装 Python 3；Windows 可从 [Python 官网](https://www.python.org/downloads/)安装，macOS／Linux 缺少 Python 时可让 Kimi 按当前系统安装。以下把 TCCLI 装进独立目录。

macOS／Linux：

```sh
python3 -m venv "$HOME/.venvs/tccli"
"$HOME/.venvs/tccli/bin/python" -m pip install --upgrade tccli
source "$HOME/.venvs/tccli/bin/activate"
tccli --version
```

Windows PowerShell：

```powershell
py -3 -m venv "$env:USERPROFILE\.venvs\tccli"
& "$env:USERPROFILE\.venvs\tccli\Scripts\python.exe" -m pip install --upgrade tccli
& "$env:USERPROFILE\.venvs\tccli\Scripts\tccli.exe" --version
```

Windows 后续把 `tccli` 替换为上面的完整程序路径，并在前面保留 `&`。macOS／Linux 新开终端后，重新执行 `source` 那一行。[TCCLI 官方安装说明](https://cloud.tencent.com/document/product/440/34011)

### 连接腾讯云账号

由企业云管理员在 [CAM 控制台](https://console.cloud.tencent.com/cam) 创建部署子账号，授予所需的 CVM、网络、安全组及 DNS 操作权限，并生成 API 密钥。不要使用主账号密钥，也不必授予全部云服务权限。

在自己的终端执行：

```sh
tccli configure
```

按提示输入 `SecretId`、`SecretKey`、地域和输出格式。上海地域填 `ap-shanghai`，输出格式填 `json`。密钥由本人输入，不粘贴进 Kimi 对话或文档。[配置说明](https://cloud.tencent.com/document/product/440/34012)

执行一次只读查询：

```sh
tccli cvm DescribeInstances --Limit 20 --region ap-shanghai
```

应能看到刚购买的实例；看不到时，先核对地域和子账号权限。使用轻量服务器的账号不能用这条 CVM 查询代替轻量实例查询。

### 确认能登录服务器

从 CVM 控制台记录公网 IP 和登录用户名，并保存购买时使用的 SSH 私钥。下面以 `ubuntu` 为例；替换文件路径和 IP：

```sh
ssh -i /你的私钥路径/tradept.pem ubuntu@服务器公网IP
```

Windows 可在 PowerShell 使用同样的 `ssh` 命令，私钥路径含空格时加双引号。首次连接前，在云控制台核对服务器身份；进入后运行 `whoami`，应显示登录用户名。完成后输入 `exit` 回到本机。若提示私钥权限过宽，macOS／Linux 执行 `chmod 600 私钥路径`；Windows 让 Kimi 调整该文件的访问权限。

## 5. 把安装工作交给 Kimi

将本指南、[Kimi 部署附录](Tradept-Kimi部署附录.md)、填好的信息表和开发方提供的部署材料放在同一个工作目录。在该目录启动 `kimi`，把下面这段话复制给它，先替换方括号内容：

```text
请根据《Tradept 企业私有部署指南》和《Tradept Kimi 部署附录》，
为一家企业部署 Tradept。请实际执行安装和检查，每完成一步再继续。

服务器公网 IP：[填写]
SSH 用户：[填写，例如 ubuntu，以控制台显示为准]
SSH 私钥在本机的路径：[填写；不要读取或输出私钥内容]
腾讯云地域：[填写，例如 ap-guangzhou]
企业网址：https://[填写]
部署版本及提交：[开发方确认的版本和完整提交号]
企业名称／管理员邮箱：[填写]
邮箱准入规则：[填写]
SMTP 服务器／端口／加密方式／发件地址：[填写]
访问范围：[公网员工访问，或公司 IP／VPN]

先只读检查服务器、磁盘、域名、版本和安装材料。
这是一家企业独享的服务器，只建一个业务站点；不要导入示例企业。
使用已正式发布且验收通过的私有初始化功能，部署时生成唯一初始管理员。
不保留演示账号，不使用默认密码，不在对话中展示生成的账号密码。
管理员先完成邮箱验证，再开通员工和业务操作；未配置 SMTP 不能算业务可用。
用 SSH 安装软件，用 TCCLI 查询与配置腾讯云资源。
凭据由我在本地终端输入，或通过受限权限文件提供；不要回显。
先生成具体部署配置，再执行；缺少镜像、依赖或初始化材料时明确列出，
不要猜测镜像地址、跳过校验或临时补写业务功能。
购买、重装磁盘和删除现有数据前，先说明对象及费用／影响并等我确认。
最后完成 HTTPS、真实登录、业务保存、权限、重启和备份恢复检查，
交付入口、版本、操作命令和备份位置。
```

正常安装结果应包括：Tradept 网页、Python 网关、带 `tradept_core` 的 ERPNext、MariaDB 数据库、Redis、后台任务服务、HTTPS 证书和自动备份。这些都运行在企业服务器上，业务数据不需要另存到 CloudBase。

私有部署仍会用到外部服务：部署时 Kimi 接收对话及工具上下文；运行时汇率和企业邮箱需要出站连接。不要把客户明细、数据库备份或密码交给 Kimi 阅读。

## 6. 管理员完成企业初始化

以下为 0.4.0 候选定义的私有初始化流程，须随正式版本验收后使用；0.3.0 试用不具备该流程。

1. 从企业密码库或运维人员的私有交付文件取得本次生成的初始管理员，打开企业网址登录。
2. 填写企业、公司和部门资料，核对各公司的国家／地区和本位币。
3. 在“邮箱登录”填写企业 HTTPS 网址、管理员真实邮箱和邮箱白名单，先保存。
4. 在“业务准备”配置 SMTP，启用发信并设为默认发信邮箱。
5. 回到“邮箱登录”，勾选“SMTP 已配置，保存并发送管理员验证邮件”。
6. 管理员收到邮件后打开链接，设置本人密码，再用真实邮箱登录。此时初始账号应已失效。
7. 邀请员工，设置角色及公司范围；员工打开邀请邮件，验证邮箱并设置本人密码。
8. 建立真实客户、供应商、商品、银行账户和会计科目；财务核对后再开始正式业务。

没收到邮件时，初始账号仍用于修正配置。检查发信设置、邮件队列和垃圾邮件后重发，不要重复生成初始管理员。即使选择“允许任意邮箱域名”，员工也仍须邀请、激活和授权。

公司名称、国家／地区和本位币应在建账前核对，后续账务迁移不能靠随意修改名称完成。

历史 Excel 先预览、核对再导入。只有汇总金额的历史资料，不应自动生成虚构的发票、收付款或总账。企业管理员与原生业务后台的使用权限需分别配置。

## 7. 全部通过后交给员工使用

| 检查 | 合格表现 |
|---|---|
| 网址与版本 | HTTPS 无证书警告；`/api/version` 与交付版本、提交一致 |
| 登录 | 验证邮箱后初始账号失效；旧演示账号及旧会话失效；正式管理员和员工可登录 |
| 权限 | 普通员工看不到未授权公司的数据、成本和财务操作 |
| 数据 | 保存后刷新、重新登录仍在；两人同时编辑有冲突提示，不静默覆盖 |
| 新登录功能（启用时） | 邀请邮件真实收到；白名单外账号被拒绝；激活、首次改密、找回密码均成功 |
| 新财务功能（启用时） | 财务在隔离验收数据中核对账单、部分收付、核销和账龄；无权限者操作被拒绝 |
| 重启与备份 | 重启服务器后自动恢复；备份能在隔离环境恢复并登录 |

请运维人员设置：每天备份数据库、公开／私有附件及站点配置；保留最近 7 天日备份和 4 周周备份，另存一份到企业私有 COS 或另一台服务器。备份包含加密密钥，应限制访问；同时配置磁盘、备份失败、证书和续费提醒。

每次升级前先备份，使用明确的新版本执行数据库迁移，检查通过后开放员工访问。失败时恢复对应版本及完整备份；不要只回退网页，也不要执行会删除数据卷的 `docker compose down -v`。

交接时留下五项：**企业网址、部署版本、管理员与运维负责人、备份及恢复方法、服务器／域名／证书续期安排**。密码通过企业密码库单独移交。

## 遇到问题先查这里

| 现象 | 先检查 |
|---|---|
| `tccli` 找不到／没有权限 | 是否已激活工具环境；地域、CAM 权限是否正确 |
| SSH 连接超时／拒绝登录 | 实例是否运行；22 端口是否允许本机 IP；用户名与私钥是否匹配 |
| 网址打不开／502 | DNS 是否指向新 IP；Nginx、网关及 ERP 服务是否运行 |
| 登录提示来源不符／403 | 域名、HTTPS 和 `public-origin` 是否一致；不要关闭校验 |
| 管理员一直停留在初始化 | 是否收到并完成真实邮箱验证；保存规则不等于已激活 |
| 行情过期，业务保存失败 | 服务器出站网络、汇率服务和两端签名密钥是否正确 |
