# 存储、协作与 Excel 静态审查

审查日期：2026-10-11。审查对象为当前工作区源码；结论不等于已核实线上发布版本或数据库安全规则。审查没有访问生产、没有修改生产记录。以下行号指修复前源码。

## 结论

现有“每次追加整库快照，然后按文档时间合并”的方式不能保证多人修改不覆盖。浏览器 `version + 1` 没有服务端条件更新，因此也不是原子的版本锁。最近 20 条合并和 5 分钟旧文档停用进一步让新增记录、删除标记依赖短暂的历史窗口。应先把正常写入改为数据库事务内的条件更新，再增加审计、快照和恢复；快照不能代替并发控制。

## 与需求文档的对应

需求 4.1 要求多人修改不丢失、保存失败明确提示；上面的覆盖及备份清理场景违反这一目标。4.2 将 200ms 防抖、keepalive、成功后回读写为已实现，但当前 `save()` 立即调用，keepalive 参数未使用，追加成功后没有回读内容验证。2.2 的 append-only 合并是当前实现描述，不能当作需要继续保留的通用产品约束。文档 7 把审计与快照列为后续项；本轮产品化应将审计提升到与写入事务同阶段。

## 目标存储边界

1. 服务端配置账号与角色，session 提供可见主体。tenant 为客户组织，company 为该组织下的法律/业务主体，不能把两者混为一层。所有记录、唯一约束、引用、审计、快照都携带 tenantId，主体型记录携带 companyId。
2. 当前记录是权威状态。写请求提交 expectedVersion、变化记录和幂等请求 id。首版可用租户整体 CAS（冲突较多但安全）；成熟后使用每记录 version 和批次事务，允许不同记录并行更新。
3. 服务端身份、字段权限、归属、数据校验、利润计算与 CAS 必须统一执行；客户端过滤只负责体验。隐藏的财务字段不参与客户端差异删除。
4. 与写入同一事务写入审计：requestId、actorId、tenant/company、entity/id、before/after、version、serverTime、source（表单、表格、Excel、恢复）。审计只追加，权限独立。
5. 快照独立于正常读取；包含 schemaVersion、tenant、版本、生成原因/操作者、完整性校验。恢复先预览差异，再按当前版本 CAS 创建一次新变更；保留原历史，不能把版本倒回过去。数据库备份与业务快照分开，明确 RPO/RTO 和恢复演练。
6. 浏览器持久化操作 outbox/草稿；无 ACK 不删除。加载和保存互斥、保存串行；409 保留本地编辑与原基线，不自动 load 覆盖。共享机器按用户隔离缓存。
7. 表单、可编辑表格和 Excel 都调用同一个后端写入口，拥有相同权限、校验、幂等、冲突和审计。导入支持错误行下载、明确的部分/全量提交策略，不能绕过写控制。

## 企业本地/云端数据库适配

现有 Cloud.loadConfig 只能换 CloudBase 环境/区域，不是通用数据库适配；业务状态、同步、保存与 CloudBase SDK 紧耦合。源码唯一云函数为 customLogin，没有统一业务 API。

建议稳定前端 `/api` 合同，适配器放后端，前端不直接持有数据库连接串。后端 repository 的最小能力包括按租户/主体查询、事务、条件更新/唯一约束、幂等请求、审计与快照读写。云数据库和企业自建数据库执行同一业务服务；优先交付一套经过验证的关系型后端，再单独实现 CloudBase 兼容/迁移适配。数据迁移要保留旧 ID、校验记录数/金额/引用关系，暂停旧写端后切换。

企业网络数据库可以采用企业内网部署 API 或受控连接代理，账号凭证只保存在企业/服务端配置。首期“连接企业数据库”应明确支持的版本、schema 与只读/读写模式，不承诺任意旧库结构无需映射即可使用。

## 本轮 API client 交付与集成合同

新增 `js/api-client.js`，导出单例 APIClient 及可独立构造的 BusinessAPIClient。它只访问同源 `/api`，使用 Cookie 会话，不保存密码/哈希。所有读写按同一 Promise 队列串行；request/response、ACK 基线、返回 metadata 都复制，正常调用方不能通过修改返回对象改变 expectedVersion。

| 方法                                                             | 行为                                                                                                                                                                                       |
| ---------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `session()` / `login({tenantId,username,password})` / `logout()` | 调用对应会话端点。会话的 `user.permissions` 数组/map 或角色配置决定 finance.write；登入/登出成功才重置基线。                                                                               |
| `loadData()`                                                     | 返回 `{data,exchangeRates,rateMetas,meta}`，同时保留不可变 ACK 基线；读取前或网络返回时发现本地 dirty 就抛 LOCAL_CHANGES，保留旧基线和草稿。                                               |
| `bindWorkingData(data,rates,rateMetas)`                          | DB 替换或恢复草稿对象后绑定当前可变对象，使 dirty 检测包含恢复的数据。                                                                                                                     |
| `saveData(data,rates,rateMetas)`                                 | 执行时采样当前对象，与 ACK 基线比较；只 POST 变化字段/记录，contacts 整数组替换。新字段不构造删除；缺失整个 collection 不删除该 collection。无变化不 POST。成功返回 true 并更新 lastMeta。 |
| `getLastMeta()` / `lastMeta` / `hasChanges()` / `isReady()`      | 供 Cloud/DB 接入；hasChanges 可显式传当前 DB 对象。                                                                                                                                        |
| `checkRemoteVersion()`                                           | 只读远程 meta，不切换 ACK 基线或 expectedVersion。                                                                                                                                         |
| `listSnapshots()` / `restore(snapshotId, options)`               | 快照列表不改基线。恢复必须无未提交草稿，expectedVersion 来自当前读取基线；服务端确认更高版本后要求重新 loadData，保留历史版本。                                                            |
| `resetBaseline()`                                                | 仅在明确放弃草稿/切换身份时调用，然后重新 loadData。它是解除冲突的显式入口，不是自动重试。                                                                                                 |
| `drainQueue()`                                                   | 等待已排队操作结束。                                                                                                                                                                       |

409 统一抛 `Error {code:'CONFLICT',status:409,latestVersion?}`，冻结该 client 后续排队保存；没有自动 load、递增版本或重试。普通角色旧表单生成的成本/收付款零值及嵌套工厂成本不会进入 patch；派生利润/审计字段始终交给服务端计算。服务端仍必须独立校验直接请求，客户端过滤不能替代权限。

`npm test -- --runInBand tests/api-client.test.js`：27 项定向测试通过（2026-10-11）。包含 409 基线/草稿保持与阻止排队重试、独立记录 patch、软删除/新增全部实体、无变化不写、网络失败、contacts 编辑/删除、ACK 后新 mutation、排队期间新 mutation、读写互斥、读取中新增草稿、权限隐藏字段保护、汇率 patch、快照 CAS 与会话 Cookie。这些结果证明 client 逻辑；后端事务、生产环境安全规则、跨进程持久化和真实备份恢复仍需各自验证。
