## 结论

六步引导的顺序合理，已修正文档中可确认的问题。但当前还不能证明“只给仓库地址即可完成全新服务器部署”：正式 Release 缺少安装附件，且本次没有执行空服务器安装、真实登录、重启和恢复试验。

## 已核对的事实

- GitHub API 返回 `wuyinhust/trade-adept` 为私有仓库；部署者及其 AI 需要获授权的身份。
- [v0.4.1 Release](https://github.com/wuyinhust/trade-adept/releases/tag/v0.4.1) 为正式发布，目标提交 `a658476c2de8fddea2afc351bdef9b127d587922`，但 `assets` 为空。自动提供的源码压缩包不包含可证明完整的离线安装材料。
- `unified_build.py` 强制核验三份 wheels 的哈希：`setuptools-84.0.0`、`wheel-0.48.0`、`packaging-26.3`。这份脚本及 `login_setup.py`、`domain.py` 与远端 v0.4.1 文件的 Git blob SHA 一致。
- 空企业初始化接口允许待初始化企业暂时没有公司；默认管理员角色包含商品与财务权限。账号登录支持不配置 SMTP。无需为了走通文档而导入演示企业。
- 仓库 Compose 是测试环境结构；企业部署仍需要生成固定项目名、持久卷、站点映射、密钥、systemd 和 HTTPS 配置。本次没有将这些模板当成已运行的企业安装器。

## 已修正的文档问题

| 问题 | 修正 |
|---|---|
| 容易在确认材料前付款，域名也可能早于地域确定 | 先核验材料，再选全套方案，统一到购买步骤付款；大陆方案付款前检查备案资格 |
| `exec backend` 时 backend 尚未启动 | 数据库／Redis、configurator、create-site、backend 分段启动；检查退出状态后才初始化企业 |
| Compose 命令未始终固定项目名 | 所有命令共用固定项目名，避免建出另一组空卷 |
| 只要求文件 0600，没说明归属 | 指定网关、运维账户、容器 Bench 用户分别需要的所有权 |
| Host／site 映射可能被误改成只接受公网域名 | 给出回环 Host 加固定 site header 的实际映射例子 |
| Python 版本与 `hashlib.file_digest` 不匹配 | 明确宿主与部署电脑使用 Python 3.11 或更高版本 |
| 预构建镜像与企业 logo 替换条件不清 | 后端 logo 定制也须备齐重建材料，并记录企业变更清单 |
| 检出旧标签后可能丢失新部署文档 | 先保存 README 和附件；执行接口仍以冻结标签为准 |

## 要达到可交付状态，还需完成

1. **发布材料**：在 trade-adept 提供经过校验的对应架构镜像，或完整离线 wheels、基础镜像获取方式及构建清单；补充源码清单与发布标识的生成方法。不能编造镜像地址或关闭现有哈希验证。
2. **全新环境演练**：在隔离空服务器按这些文件完整部署，使用空企业、自选管理员、账号登录；记录系统和硬件规格、实际生成配置及命令。没有镜像或依赖材料时先补材料，不让客户用付费服务器试错。
3. **运行验收**：真实 HTTPS 登录、企业初始化、权限、商品与业务保存、并发冲突、重启持久化；选择备份时完成异机下载和隔离恢复。选择 logo 替换时检查浅深色与镜像重建后持久性。

2 核 4 GB 等配置是筛选起点，尚不能据此次文档核查认定容量足够。本次只做代码／文档检查及静态校验，没有购买资源、修改现网或把既有 Grandware 升级成功当成空企业安装成功。
