# 统一系统的云测试部署

0.2.0 使用与本地相同的 Frappe/ERPNext + `tradept_core`。网关不保存业务数据库，配置固定企业站点地址；数据库、site 文件、日志及备份使用独立持久盘。每个企业 site/database 隔离，Grandware 多公司在一个站点内。

旧 SQLite 云部署属于 `archive/parallel-systems-v0.1.1`，不能用旧 init、复制 SQLite 或旧 outbox 步骤启动新版。当前公网测试域名仍运行 0.1.1；源码更新和实际云部署状态须分别回读。

## 资源与拓扑

完整 ERP 需要 MariaDB、Redis、web、worker、scheduler 和持久卷。本轮现有云机为 2CPU/2GB 且共享其他应用，不能直接叠加完整 ERP 作为可靠新版部署。优先使用已有独立资源，或在确认规格与费用后准备独立至少 4GB 测试主机；该建议不是本轮已采购或已部署证明。

浏览器 → 专用 HTTPS 域名反向代理 → 回环 Tradept 网关 → 固定 Frappe 站点。可连接企业已有本地或云端 Frappe 后端。直接连接任意企业数据库并绕过 Frappe 权限不在此方案内。

## 具体部署

1. 安装固定版本 ERPNext 与包含 `tradept_core` 的可重建镜像，建立独立 site/database 和持久卷，限制内部服务端口。
2. 通过可信管理员配置公司和原生 User，迁移前完整备份，使用只读源文件哈希、逐记录比较和显式原生单据对账验证迁移。
3. 在网关私有持久目录安装 `frappe-sites.json`；只允许固定 `origin` 和 `site`，禁止共享同一站点、HTTP 远端、URL 口令和重定向。
4. 使用 [systemd 模板](tradept-test.service) 和固定 `TRADE_PUBLIC_ORIGIN`，保留已有域名的有效 HTTPS / 续期配置。反向代理传原 Host，不能接受客户端伪造 forwarded origin。
5. 先在独立端口验收，验证原生登录、两租户、角色字段、CAS、Excel、收付款、重启持久化及备份恢复，再切换单一公开入口。

所有凭据、私有配置、数据库与客户导出不进入 Git。停止旧写入进程和旧 ERP 集成账号，避免两个版本同时操作同一业务库。失败回退使用完整原生备份与对应代码版本，不恢复 JSON 快照覆盖已提交财务单据。

## 验收边界

CI 网关和规则测试证明协议及校验逻辑；真实数据库和部署测试另行记录。当前隔离本地验证结果不能视为公网已升级。完整电子表格、商业计费及更广泛原生业务入口仍须逐项交付与验收。
